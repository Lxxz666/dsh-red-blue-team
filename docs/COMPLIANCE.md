# 合规声明（COMPLIANCE）

## ⚠️ 最高优先级红线

**本项目仅用于安全研究、授权测试与教学目的。**

1. **只测授权目标**：发起任何攻击性扫描前，必须获得目标系统所有者的**书面授权**。
   内置靶场（`target_lab`）、自建系统、授权内网测试环境默认视为已授权。
2. **禁止未授权扫描**：对公网未授权系统发起扫描/攻击属于违法行为，
   任何演示都必须使用内置靶场。
3. **免责声明**：对未授权系统的任何测试行为，由使用者自行承担全部法律责任。

## 技术闸门（系统内置强制）

| 闸门 | 位置 | 行为 |
|:--|:--|:--|
| 授权校验 | `redteam/config.py` | 非本地目标（非 127.0.0.1/localhost）缺少 `authorization` 块 → 拒绝扫描（退出码 2） |
| 文件夹扫描豁免 | `redteam/config.py` | 本地文件夹静态扫描（type=folder）只读审计自有代码，不发起网络攻击，无需授权声明 |
| 授权留存 | `scan.yml → audit` | 每次扫描的配置路径与授权声明写入事件溯源审计日志 |
| 节流保护 | `engine.min_interval_ms` / `concurrency` | 内置请求节流与并发上限，防把目标打挂 |
| 端点发现约束 | `redteam/agents/worker.py` | 场景识别端点探测仅限有界 GET 列表、低频、非 404 即停，无暴力枚举 |
| 状态隔离 | 状态型样本串行通道 + 靶场 `/_admin/reset` | 每次攻击独立状态，不污染目标生产数据 |
| 5xx 保护 | detector | 目标返回 5xx 计入 error 并触发错误预算，不计为漏洞 |
| 蓝队红线 | `redteam/blueteam/engine.py` | 只改沙箱/靶场（guards 文件，备份+版本化+可回滚）；外部目标只输出方案（manual_only），绝不自动修改 |

## 授权声明格式（scan.yml）

```yaml
authorization:
  authorized_by: "目标所有者/安全负责人姓名与职位"
  contact: "sec@example.com"
  scope: "仅限授权范围内的测试环境：<具体域名/IP/时间段>"
  note: "授权书编号/存档路径（可选）"
```

## 靶场说明

`target_lab` 是一个**故意埋入 23 个漏洞**的演示系统（弱防护电商客服 agent），
仅在本地 127.0.0.1 上运行：

- 所有"漏洞"由 `guards.yml` 防护配置显式控制，不存在真实数据风险；
- 内置密钥（`SK-LAB-*`）为虚构值，仅用于检测器校准与演示；
- 靶场只监听 loopback 地址，不接受外网连接。

## 使用建议

- 企业内网/生产系统测试：仅限书面授权范围，建议先 clone 环境再测；
- 交付报告中的证据（攻击载荷/响应）属敏感材料，注意传输与存储安全；
- 安全研究者请遵守所在司法辖区的法律法规（如中国《网络安全法》《数据安全法》）。

## 伦理声明

> 本项目用于让**系统所有者**发现自己系统的漏洞并修复它（红队→蓝队闭环），
> 而不是为攻击者提供武器。样本库中的攻击载荷均为公开学术资料中的标准
> 检测载荷（OWASP/Garak/PyRIT 等），请负责任地使用。
