## 2. Memory 分节

### 2.1 定位与依赖

- 对应 TS 版 mcp-memory 示例的「内部记忆」形态：零外部进程、零 MCP 握手，
  直接把「长期记忆」作为一等服务（`ctx.memory`）+ 四个工具接入 agent。
- `MemoryService.provides = "memory"`；`ToolMemoryPlugin.inject = ("tools", "memory")`。
- 持久化：`ctx.storage` domain `"memory"`，条目表存键 `_entries`（`_persist`
  用 `storage.put(STORAGE_DOMAIN, "_entries", dict(...))`）；**未挂载 storage
  则仅内存**（同 feedback 的降级约定）。`apply` 时 `storage.get(STORAGE_DOMAIN,
  "_entries") or {}` 恢复。
- 事件：每次变更广播 `memory/changed` {op: add|remove|clear}（异常隔离）。

### 2.2 模块级函数

- `_WORD_RE = re.compile(r"[0-9a-z_]+")`、`_CJK_RE = re.compile(r"[\u4e00-\u9fff]+")`：模块常量。
- `_tokenize(text: str) -> set`
  - `folded = (text or "").casefold()`；`tokens = set(_WORD_RE.findall(folded))`；
  - 对每个连续 CJK 片段（`_CJK_RE.findall`）：长度 >1 时加**相邻二字组**
    `run[i:i+2]`（中文无需分词即可命中），长度 1 时加 `run` 本身。
- `_jaccard(a: set, b: set) -> float`：`if not a or not b: return 0.0`；
  `len(a & b) / len(a | b)`。

### 2.3 MemoryService 函数/方法详解

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `_entries` | `Dict[str, Dict]` | `{}` | `entry_id -> {id, content, tags, created_at}` |

- `__init__(self, ctx, config=None)`：仅 `self._entries = {}`。
- `apply(self, ctx) -> None`：`ctx.set("memory", self)`；`ctx.has("storage")` 时
  `self._entries = ctx.storage.get(STORAGE_DOMAIN, "_entries") or {}`。
- `_persist(self) -> None`：有 storage → `put(STORAGE_DOMAIN, "_entries", dict(self._entries))`。
- `_emit(self, op: str) -> None`：`try: emit("memory/changed", {"op": op}) except: pass`。
- `add(self, content: str, tags: Optional[List[str]] = None) -> Dict[str, Any]`
  - `not (content or "").strip()` → `raise ValueError("memory content must not be empty")`；
  - `entry = {id: uuid4().hex[:12], content, tags: [str(t) for t in (tags or [])],
    created_at: int(time.time()*1000)}`；写入 `_entries` → `_persist()` → `_emit("add")`；
  - 返回 `dict(entry)`。
- `get(self, entry_id: str) -> Optional[Dict]`：存在返回副本，无则 None。
- `list(self, limit: int = 100) -> List[Dict]`：按 `created_at` 降序
  （`key=lambda e: e.get("created_at", 0), reverse=True`），截取 `[:max(0, int(limit))]`。
- `search(self, query: str, limit: int = 5) -> List[Dict]`
  - `query_tokens = _tokenize(query)`；空 → `[]`；
  - 每个条目：`haystack = " ".join([content, *tags])`；`score = _jaccard(query_tokens,
    _tokenize(haystack))`；`score > 0` 才入选；
  - 排序 `key=(score, created_at)` 降序（**同分按时间倒序**——新记忆优先）；
  - 返回 `dict(entry, score=round(score, 4))` 列表。
- `remove(self, entry_id: str) -> bool`：存在 → 删除 + `_persist` + `_emit("remove")`
  返回 True；否则 False。
- `clear(self) -> None`：清空 + `_persist` + `_emit("clear")`。
- `close(self) -> None`：`_entries.clear()`。

### 2.4 工具

| 工具 | 参数 | 输出 | 行为 |
|---|---|---|---|
| `memory_add` | `content`（string，required）、`tags`（string 数组，可选） | object | `root_ctx.memory.add(content, tags)` → 条目 |
| `memory_search` | `query`（string，required）、`limit`（integer，default 5） | array | `root_ctx.memory.search(...)` → 带 score 的条目列表 |
| `memory_list` | `limit`（integer，default 100） | array | `root_ctx.memory.list(...)` |
| `memory_remove` | `id`（string，required） | boolean | `root_ctx.memory.remove(id)` |

- 工具全部经 `run_ctx.root_ctx.memory` 取服务（与作用域无关，记忆是全局设施）。
- `ToolMemoryPlugin.apply`：依次 `ctx.tools.register(factory())` 四个工具，
  返回 `cleanup()`（逐个调用 disposer 并清空）。

### 2.5 边界

- Jaccard 检索是**词汇级**相似度（无向量嵌入）；标签参与检索（拼进 haystack）。
- 空内容拒绝（ValueError 冒泡为工具错误）。

## 3. AgentPresets.recompose 分节

（完整 preset 机制见手册 12 §2.10；此处只记换绑语义。）

- `async recompose(self, agent_ctx: Any, preset_id: str) -> Dict[str, Any]`：
  1. `key = id(agent_ctx)`；`record = self._mounted.pop(key, None)`；
  2. record 非空 → `await tree.dispose(dispose_ctx=False)`：close 各插件实例 +
     执行 apply 返回的 disposer（旧工具从作用域层注销）+ 清空树索引；**不销毁作用域**；
  3. `result = await self.mount(agent_ctx, preset_id)`：作用域级局部 ToolRuntime
     已存在则复用（新树的工具注册到同一层）；
  4. `result["recomposed"] = True` 返回。
- **契约**：调用方负责「agent 尚未产生任何对外输出」检查；本方法不拦截。
- **幂等/安全性**：旧树 `dispose` 可重复调用（`_rollback` 清空 `_mounted` 索引，
  第二次为空转）；作用域销毁时旧 mount 注册的 `dispose_tree` effect 重放无害；
  新 mount 注册的新 effect 正常逆序回滚。
- **失败语义**：新 preset 不存在/组合不可用时 `LoaderError` 向上抛，旧树已卸
  （fail loud，不残留半更新状态）。

## 4. workflow 结构化输出分节

（引擎整体见手册 14 §2.8；此处只记第六批增量。）

- spec 的 step 新增可选键 `output`（JSON Schema，受支持子集，见手册 03）。
- `_run_step` 在 `value = _parse_value(text)` 之后：

  ```
  output_schema = step.get("output")
  if output_schema:
      try:
          validate_value(value, output_schema, what=f"workflow step {step_name} output")
      except ToolError as exc:
          value = {"invalid_output": True, "value": value, "error": str(exc)}
  ```

  - 通过 → 原值不动；失败 → **不抛错**（单步隔离约定保持），替换为
    `{invalid_output: True, value: 原值, error: 消息}`；
  - `workflow/agent-end` 仍以 `ok: True` 派发（校验失败是「结果不合格」而非
    「执行失败」，由调用方按 `invalid_output` 标记处理）。
- `workflow_run` 工具的 steps item schema 同步放行 `output`（object 注解：
  不匹配时结果带 invalid_output）。

## 5. agent/request-done 观测分节

- 位置：`AgentLoopService._run_step`，流式请求成功、`assistant/message` 落日志
  **之后**、工具执行之前。
- 计时：请求发起前 `started_ms = int(_time.perf_counter() * 1000)`；广播时
  `latency_ms = int(_time.perf_counter() * 1000) - started_ms`。
- 载荷：`{agent, turn, step, provider, model, usage, latency_ms}`
  （`usage` 来自 `assembler.finish()["usage"]`，mock 无计量时为 None）。
- 用途：指标/观测消费者（如 telemetry 后端）挂一个 emit 监听即可；请求失败
  （LlmFailure）不广播（走 `agent/request-error`）。
