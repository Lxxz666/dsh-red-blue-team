## 2. 逐子系统分节

> 通用约定：以下类都继承 `kernel.Service`。`Service.__init__(ctx, config)` 记录
> `self.ctx`、`self.config = config or {}`、`self._disposer = None`。
> `apply(ctx)` 的返回值是「清理函数（disposer）」，由 `PluginTree.mount` 存到
> `MountedPlugin.disposer`（当前代码路径未在卸载流程调用该字段；`Service.close()`
> 只调用 `self._disposer`，而这些插件未自行赋值，故继承的 `close()` 对「apply 返回
> cleanup」类插件实际是空操作——测试里 `AgentInstructionsPlugin` 是手动 `cancel()`
> 轮询任务来停它的）。

### 2.0 共享词汇速查（被多个子系统引用）

这些类型不是本批新增，但多个子系统依赖其结构，理解它们有助于读下文：

| 类型 | 关键字段/签名 | 本批消费方 |
|---|---|---|
| `llm.messages.ContentBlock`（frozen dataclass） | `kind, text, call_id, name, arguments, tool_call_id, content, is_error, extra`；`kind="tool-result"` 时值在 `content`、身份在 `tool_call_id` | pruner（读 `content`/`tool_call_id`/`is_error`）、tokenMeter（读 `text`） |
| `llm.messages.Message`（frozen dataclass） | `id, role, content(List[ContentBlock]), source(Dict)`；`plain_text()` 拼接 text/reasoning | pruner（重建）、tokenMeter（遍历）、compaction（`plain_text` 摘要） |
| `session.SessionHeader`（dataclass） | `version, id, created_at, cwd, parent_session, seed_length, origin, delegation_depth, agent_preset` | query（`list`/`trace` 投影）、subagent（fork 血缘） |
| `tools.pipeline.AbortSignal` | `aborted, reason`；`abort(reason)` 幂等（首个 reason 胜出）；`wait()` 挂起直到取消 | `Agent.run_maintenance` 传给维护任务 |
| `prompt.system_prompt.PromptSection`（dataclass） | `name, order, text(str|callable), complete=False`；`resolve(ctx)` 对 callable 求值 | instructions 根分节（`order=5`） |
| `kernel.Context` | `has(key)` / `set(key, instance)` / `on(name, handler, *, prepend=False)->Disposer` / `effect(disposer)` / `events.emit` | 全部服务（挂载、事件订阅/派发） |

事件总线要点：`ctx.events.emit(name, payload)` 同步派发；本批服务中
`credentials/updated`、`message-feedback/updated`、`workflow/*` 的派发都包了
`try/except`（`credentials.delete` 例外，未包）；`system-prompt/change` 由
`systemPrompt.section` 内部派发，不由本批代码直接发。

### 2.1 凭据 CredentialsService

**定位与依赖**：`provides = "credentials"`，无 `inject`。文件后端 `.credentials.yaml`
（默认 `~/.dsh/.credentials.yaml`，`config.path` 可换）。消费方为
`DeepSeekAdapterPlugin`（见 2.9）。

**类型与字段表**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `path` | `str` | `os.path.expanduser` 展开后的 YAML 文件路径 |
| `_lock` | `threading.Lock` | 串行化落盘写（`_save` 使用） |
| `_data` | `Dict[str, Any]` | 内存缓存：name → 值 |

**函数/方法详解**：

- `__init__(self, ctx, config: Optional[dict] = None) -> None`
  - 参数：`ctx`(Context) 内核上下文；`config`(dict|None, 默认 None) 配置。
  - 设置 `self.path`；初始化锁与空 `_data`；调用 `self._load()`。
- `apply(self, ctx) -> None`
  - `ctx.set("credentials", self)`；无返回值、无 disposer。
- `_load(self) -> None`
  - `open(path, "r", encoding="utf-8")` + `yaml.safe_load`；捕获
    `(OSError, yaml.YAMLError)` 置 `_data = {}`；`safe_load` 返回 `None`（空文件）
    归一为 `{}`。
- `_save(self) -> None`
  - 持 `_lock`；`os.makedirs(os.path.dirname(self.path), exist_ok=True)` 建父目录；
    `yaml.safe_dump(self._data, fh, allow_unicode=True)` 全量覆盖写盘。
- `get(self, name: str) -> Any`
  - 返回 `self._data.get(name)`；不存在返回 `None`。
- `set(self, name: str, value: Any) -> None`
  - `self._data[name] = value` → `_save()` →
    `try: self.ctx.events.emit("credentials/updated", {"name": name}) except Exception: pass`。
  - 副作用：落盘 + 事件派发；派发异常被吞。
- `delete(self, name: str) -> None`
  - 仅当 `name in self._data`：`del` → `_save()` →
    `emit("credentials/updated", {"name": name})`（此处 **未** 包 try/except，与 `set` 不同）。
- `names(self) -> List[str]`
  - 返回 `list(self._data.keys())`；只列名不泄值。

**边界**：`_save` 用 `threading.Lock` 串行化写，但 `get`/`set`/`delete` 对 `_data`
的读写未加锁（单条 dict 操作在 CPython GIL 下近似原子，无跨方法一致性保证）；无
多进程文件锁（多进程并发写会互相覆盖）；`delete` 对不存在键静默跳过。

**TS 对应**：credentials-local 的 `get/set/delete/names` + `credentials/updated`。

**关键流程伪代码**：

```
set(name, value):
  _data[name] = value
  _save()                       # 持锁，makedirs + safe_dump 全量写
  emit("credentials/updated", {name})
```

**事件**：`credentials/updated`（载荷仅 `{"name"}`，不泄值）。

### 2.2 TokenMeter

**定位与依赖**：`provides = "tokenMeter"`，无 `inject`。纯内存、无状态。

**类型与字段/常量**：模块常量 `TOKENS_PER_CHAR = 4`；实例无自定义字段。

**函数/方法详解**：

- `__init__(self, ctx, config: Optional[dict] = None) -> None`
  - 仅调 `super().__init__(ctx, config)`。
- `apply(self, ctx) -> None`
  - `ctx.set("tokenMeter", self)`。
- `estimate(self, messages: List[Any]) -> int`
  - 参数：`messages`(List[Any]) Message 列表（含 content 块）。
  - 对每条 message 取 `getattr(message, "content", [])` 迭代块，对每块取
    `getattr(block, "text", None)`；`text` 真值时累加 `len(text) // TOKENS_PER_CHAR`。
  - **注意**：只统计 `block.text`，不统计 `block.content`（tool-result 的 `content`
    不参与计量）；每块独立地板除后求和（非拼接后整除）。
- `count_text(self, text: str) -> int`
  - `len(text) // TOKENS_PER_CHAR`。

**边界**：无异常路径、无事件、无并发状态。

**TS 对应**：token-meter 的粗粒度估算（4 字符≈1 token）。

### 2.3 AGENTS.md 指令注入 AgentInstructionsPlugin

**定位与依赖**：`inject = ("systemPrompt",)`（无 provides，纯副作用插件）。可选依赖
`ctx.fs`（缺省退回 `os.getcwd()`）与 `ctx.agents`（注入目标，可选）。

**类型与字段表**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `interval` | `float` | 轮询间隔秒（`config.interval`，默认 `2.0`） |
| `_disposers` | `List[Any]` | 记录 prompt 分节 disposer |
| `_watcher_task` | `Optional[asyncio.Task]` | 子目录轮询任务 |
| `_seen` | `Dict[str, tuple]` | 上次扫描 `{path: (mtime_ns, size)}` |
| `_root_seen` | `Optional[tuple]` | 声明但 **未使用** |

模块常量：`AGENTS_FILENAME = "AGENTS.md"`；`_SKIP_DIRS = {".git", "__pycache__",
".venv", "node_modules", ".dsh", ".pytest_cache", "__pycache__"}`（`__pycache__`
重复出现两次，集合去重）。

**函数/方法详解**：

- `__init__(self, ctx, config: Optional[dict] = None) -> None`
  - `self.interval = float((config or {}).get("interval", 2.0))`；初始化
    `_disposers=[]`、`_watcher_task=None`、`_seen={}`、`_root_seen=None`。
- `apply(self, ctx) -> None`
  - 构造 `PromptSection(name="agent-instructions", order=5,
    text=lambda _ac: self._read_root_instructions())`（`text` 为 callable → 每次
    assemble 实时重读根文件，改动即时生效）。
  - `self._disposers.append(ctx.systemPrompt.section(section))`。
  - `try: loop = asyncio.get_running_loop(); self._watcher_task =
    loop.create_task(self._watch_loop())`；`except RuntimeError: self._watcher_task = None`
    （非异步挂载时跳过轮询）。
  - 返回 `cleanup()` 闭包：逆序调用全部 disposer、清空 `_disposers`、取消
    `_watcher_task` 并置 None。
- `_workspace(self) -> str`
  - `ctx.has("fs")` 时 `ctx.fs.workspace_root()`，否则 `os.getcwd()`。
- `_read_root_instructions(self) -> str`
  - 读 `<workspace>/AGENTS.md`；不存在返回 `""`；读失败（`OSError`）返回 `""`。
- `_scan(self) -> Dict[str, tuple]`
  - `os.walk(root)`；`dirnames[:]` 过滤 `_SKIP_DIRS`；发现 `AGENTS.md` 时跳过根文件
    （由分节负责），其余 `os.stat` 记录 `(st_mtime_ns, st_size)`；整段
    `try/except OSError: pass`。
- `async _watch_loop(self) -> None`
  - `while True`: `await asyncio.sleep(self.interval)` → `current = self._scan()` →
    `changed = {p: s for p,s in current.items() if self._seen.get(p) != s}` →
    `self._seen = current`。
  - `changed` 为空或 `not ctx.has("agents")` 则 `continue`。
  - 对每个变更 path：读内容（`OSError` 则 `continue`）→
    `rel = os.path.relpath(path, self._workspace())` → 对 `ctx.agents.list()` 中每个
    非 `_disposed` 的 agent 调 `agent.inject(f"[指令更新] {rel}\n{content}",
    source={"kind":"plugin","plugin":"agent-instructions","form":"instructions"})`。
  - `except asyncio.CancelledError: raise`；其它异常 `log.exception` 后循环死亡
    （不再自动重启）。

**事件/副作用**：根分节经 `systemPrompt.section` 触发 `system-prompt/change`；子目录
变更不派发事件，只经 `agent.inject`（`next-step` 收件箱，不唤醒驱动）投递。

**TS 对应**：agent-instructions 的根分节 + on-touch 子目录注入。

**关键流程伪代码**：

```
apply(ctx):
  section = PromptSection(name="agent-instructions", order=5,
                          text=lambda: read_root_instructions())
  systemPrompt.section(section)
  watcher_task = loop.create_task(watch_loop())   # 无 running loop 则跳过

watch_loop():
  loop:
    sleep(interval)
    current = scan()                 # os.walk + (mtime_ns, size)
    changed = {p for p in current if _seen[p] != current[p]}
    _seen = current
    if changed and ctx.has("agents"):
      for path in changed:
        for agent in ctx.agents.list() if not disposed:
          agent.inject("[指令更新] <rel>\n<content>", source=...)
```

### 2.4 工具结果修剪 ToolResultPrunerService

**定位与依赖**：`provides = "toolResultPruner"`，无 `inject`。依赖
`llm.messages.ContentBlock`/`Message` 结构（`Message` 为 frozen dataclass）。

**类型与字段表**：`max_chars`（`int`，`config.max_chars`，默认 `4000`）。

**函数/方法详解**：

- `__init__(self, ctx, config: Optional[dict] = None) -> None`
  - `self.max_chars = int((config or {}).get("max_chars", 4000))`。
- `apply(self, ctx) -> None`
  - `ctx.set("toolResultPruner", self)`。
- `prune(self, messages: List[Message]) -> List[Message]`
  - 参数：`messages`(List[Message]) 待修剪消息列表。
  - 遍历每条 message；对每个 `block`：若 `block.kind == "tool-result"` 且
    `len(str(block.content or "")) > self.max_chars`，则重建
    `ContentBlock(kind="tool-result", tool_call_id=block.tool_call_id,
    content=截断文本, is_error=block.is_error)`，置 `changed = True`。
  - 截断文本 = `text[:max_chars] + f"\n...[截断 {len(text) - max_chars} 字符]"`。
  - 若 `changed`：重建 `Message(id=message.id, role=message.role, content=blocks,
    source=dict(message.source))`（`source` 浅拷贝）；否则原对象原样追加。
  - **不改原对象**；只修剪 `tool-result` 块，其它块原样保留。
- `prune_text(self, text: str) -> str`
  - 单段文本：`len(text) <= max_chars` 原样返回；否则同规则截断（含标记）。

**边界**：无异常路径、无事件；截断标记为中文固定串 `...[截断 N 字符]`。

**TS 对应**：compaction-tool-result-pruner——压缩摘要前的可选修剪步骤，降低摘要
输入体积。

### 2.5 Agent.runMaintenance / _run_maintenance / cancel / when_idle

> `Agent` 类（`dsh/agent/agent.py`）第二批新增/强化的部分。字段
> `_maintenance: Optional[asyncio.Task]` 记录 true idle 阶段的维护任务
> （docstring：「runMaintenance 启动，cancel 中止」）。

**函数/方法详解**：

- `run_maintenance(self, task) -> asyncio.Task`
  - 参数：`task`，形如 `async def task(signal: AbortSignal) -> T`。
  - 前置检查：`self.status == "running"` 或 `self._maintenance is not None` →
    `AgentError(f"agent {self.id} busy")`；`self._disposed.is_set()` →
    `AgentError(f"agent {self.id} disposed")`。
  - 建 `AbortSignal`（`dsh/tools/pipeline.py`）；`self._maintenance =
    asyncio.get_running_loop().create_task(self._run_maintenance(task, signal))`；
    返回该 `asyncio.Task`。
  - **公共状态保持 `idle`**（不调用 `_set_status("running")`，故不派发
    `agent/status`）；须在异步上下文调用（`get_running_loop()`）。
- `_run_maintenance(self, task, signal) -> Any`
  - `try: return await task(signal)`；`finally: self._maintenance = None`。
  - 任务完成/被取消都清空 `_maintenance`。
- `cancel(self, cause: Optional[Dict[str, Any]] = None, keep_inbox: bool = False) -> None`
  - 参数：`cause`(dict|None) `{'kind':'user'|'parent'|'hook'|'disposed', ...}`；
    `keep_inbox`(bool, 默认 False)。
  - `disposed` 则直接返回；`_cancel_cause` 首个 cause 胜出（`cause or {"kind":"user"}`）。
  - `not keep_inbox` 时：对 `inbox.next_turn + inbox.next_step` 各发
    `agent/inbox/discarded`，然后 `inbox.clear()`。
  - 若 `_turn_signal is not None`：`_turn_signal.abort(self._cancel_cause)`。
  - **新增**：若 `_maintenance is not None`：`self._maintenance.cancel()`。
  - `self._wakeup.set()`（唤醒驱动，令 `when_idle` 的等待循环重新检查）。
- `when_idle(self) -> None`（async）
  - `while True`: `await self._idle.wait()`；当 `not self._wakeup.is_set()` 且
    `not self.inbox.has_next_step()` 且 `not self.inbox.has_next_turn()`：
    - 若 `_maintenance is not None`：`await asyncio.gather(self._maintenance,
      return_exceptions=True)` 后 `continue`（等维护任务完成再查）；
    - 否则 `return`。
  - 否则 `await asyncio.sleep(0)` 让出事件循环再查。
  - **关键保证**：同时检查 `_idle` 标志、`_wakeup`、收件箱，避免「刚排队消息、驱动
    尚未开始处理」时提前返回（子代理等待场景）。
- `dispose(self, cause: Optional[Dict[str, Any]] = None) -> None`
  - `cancel(cause or {"kind":"disposed"})` → `self._disposed.set()` → `self._wakeup.set()`
    （会连带取消维护任务）。

**边界/并发**：`run_maintenance` 与 running 状态、已存在维护任务互斥（抛 `AgentError`）；
`cancel` 与 `dispose` 幂等（disposed 直接返回）；维护任务取消会经 `_run_maintenance`
的 `finally` 清空 `_maintenance`，随后 `when_idle` 可正常返回。

**TS 对应**：`runMaintenance`（true idle 维护任务）、`whenIdle`（整个 agent 静默后
resolve）、`cancel(cause, keep_inbox)`（首个 cause 胜出）。

**关键流程伪代码**：

```
run_maintenance(task):
  if running or _maintenance: raise AgentError(busy)
  if disposed: raise AgentError(disposed)
  signal = AbortSignal()
  _maintenance = loop.create_task(_run_maintenance(task, signal))
  return _maintenance          # 状态仍 idle

when_idle():
  loop:
    await _idle.wait()
    if not wakeup and not next_step and not next_turn:
      if _maintenance: await gather(_maintenance); continue
      return
    await sleep(0)
```

### 2.6 会话查询 SessionQueryService

**定位与依赖**：`provides = "sessionQuery"`。依赖 `ctx.sessionPersistence`（运行时
检查，缺失抛 `SessionError`）。

**类型与字段表**：`_default_limit`（`int`，`config.limit`，默认 `50`）。

**函数/方法详解**：

- `__init__(self, ctx, config: Optional[dict] = None) -> None`
  - `self._default_limit = int((config or {}).get("limit", 50))`。
- `apply(self, ctx) -> None`
  - `ctx.set("sessionQuery", self)`。
- `_persistence(self)`
  - `not ctx.has("sessionPersistence")` 时 `raise SessionError("sessionPersistence
    not mounted")`；否则返回 `ctx.sessionPersistence`。
- `async list(self, origin: Optional[str] = None, limit: Optional[int] = None) -> List[Dict[str, Any]]`
  - 参数：`origin`(str|None) 过滤 `SessionHeader.origin`（如 `'subagent'`）；
    `limit`(int|None) 上限，缺省用 `_default_limit`。
  - `limit = limit or self._default_limit`（**注意**：`limit=0` 被 falsy 化为默认值）。
  - 遍历 `await persistence.list_ids()`；`len(out) >= limit` 即 `break`；每个 id
    `await persistence.inspect(id)` 得 `(header, events)`（异常则 `log.exception` 后
    `continue`）；`origin is not None and header.origin != origin` 时跳过；追加摘要
    `{id, created_at, cwd, origin, parent_session, delegation_depth, events: len(events)}`。
- `async search(self, text: str, limit: Optional[int] = None) -> List[Dict[str, Any]]`
  - 参数：`text`(str) 搜索词；`limit`(int|None)。
  - `needle = text.lower()`（大小写不敏感）；逐 id `inspect`（异常静默 `continue`）。
  - 对 `user/message`、`assistant/message`、`compaction/summary` 三类事件：取
    `data.get("content", "")`（空且 `data.get("summary")` 存在时回退 summary）为
    haystack；`needle in haystack.lower()` 命中则记 `{seq, time, text: haystack[:200]}`。
  - 有命中则 append `{session_id, matches}`；`len(results) >= limit` 即停。
  - 返回 `[{"session_id", "matches": [{"seq","time","text"}]}]`。
- `async trace(self, session_id: str) -> Dict[str, Any]`
  - `header, events = await persistence.inspect(session_id)`；返回
    `{"header": {id, created_at, cwd, origin, parent_session, delegation_depth,
    agent_preset}, "events": events}`。
  - 会话不存在时由底层 `inspect/load` 抛 `SessionError`（docstring 标注）。

**边界**：`search` 静默吞 inspect 异常（坏会话跳过）；`list` 记录异常日志后跳过。

**TS 对应**：session-query 的 `list/search/trace`；走 `inspect` 全量载入（见第 3 节）。

### 2.7 消息反馈 MessageFeedbackService

**定位与依赖**：`provides = "messageFeedback"`。可选依赖 `ctx.storage`（未挂载则仅
内存）。

**类型与字段/常量**：`STORAGE_DOMAIN = "message-feedback"`；
`_memory: Dict[str, List[Dict[str, Any]]]`（session_id → 反馈记录列表）。

**函数/方法详解**：

- `__init__(self, ctx, config: Optional[dict] = None) -> None`
  - `self._memory = {}`。
- `apply(self, ctx) -> None`
  - `ctx.set("messageFeedback", self)` → `self._restore()`。
- `_restore(self) -> None`
  - `ctx.has("storage")` 时 `self._memory = self.ctx.storage.domain(STORAGE_DOMAIN)`。
- `_persist(self) -> None`
  - `ctx.has("storage")` 时对每个 `(session_id, records)` 调
    `ctx.storage.put(STORAGE_DOMAIN, session_id, list(records))`（全量覆盖该 session）。
- `put(self, session_id: str, seq: int, kind: str, note: Optional[str] = None) -> Dict[str, Any]`
  - 参数：`session_id`(str)；`seq`(int) 消息序号；`kind`(str) `'up'|'down'`；
    `note`(str|None) 附注。
  - `kind not in ("up", "down")` → `raise ValueError(f"invalid feedback kind: {kind!r}")`。
  - record = `{session_id, seq: int(seq), kind, note, time: int(time.time()*1000)}`；
    `_memory.setdefault(session_id, []).append(record)` → `_persist()` →
    `try: emit("message-feedback/updated", {"session_id"}) except Exception: pass` →
    `return dict(record)`（浅拷贝）。
- `get(self, session_id: str) -> List[Dict[str, Any]]`
  - `list(self._memory.get(session_id, []))`（列表拷贝）。
- `close(self) -> None`
  - `self._memory.clear()`（清内存，不写 storage）。

**事件**：`message-feedback/updated`（载荷 `{"session_id"}`；派发异常被吞）。

**接线**：`dsh/server/app.py` 提供 `POST /api/sessions/{id}/feedback`（写，依赖
`ctx.messageFeedback`，无则返回 `{"error":"feedback unavailable"}`）与
`GET /api/sessions/{id}/feedback`（读）；前端在助手消息上提供 👍👎。

**TS 对应**：message-feedback（storage 持久化 + Web UI + REST）。

### 2.8 最小版工作流 workflow

**定位与依赖**：`WorkflowEngine.provides = "workflowEngine"`；`ToolWorkflowPlugin.inject
= ("tools", "workflowEngine", "subagents")`。运行时依赖 `ctx.subagents.get("in-process")`
与父 Agent。

**模块级函数**：

- `_extract_json(text: str) -> Any`
  - 线性扫描每个字符；遇 `{`/`[` 起一个「配平」扫描：`depth` 计数器 + `in_str`/`escape`
    标志跳过字符串字面量；`depth` 归零时取 `text[start:i+1]` 为候选，`json.loads`
    成功即返回；失败 `break`（放弃当前起点，继续外层下一个起点）。全程无匹配返回
    `None`。用途：从夹带回显前缀的文本中提取第一个配平 JSON。
- `_parse_value(text: str) -> Any`
  - `stripped = text.strip()`；若以 `{`/`[` 开头先 `json.loads(stripped)`，成功即返回，
    失败 pass；再 `_extract_json(stripped)`，非 None 返回之；否则返回**原文 `text`**。

**WorkflowEngine 函数/方法详解**：

- `__init__(self, ctx, config: Optional[dict] = None) -> None`：仅调 super。
- `apply(self, ctx) -> None`：`ctx.set("workflowEngine", self)`。
- `_emit(self, name: str, payload: Dict[str, Any]) -> None`
  - `try: self.ctx.events.emit(name, payload) except Exception: pass`。
- `async run(self, spec: Dict[str, Any], parent: Any) -> Dict[str, Any]`
  - 参数：`spec`(Dict) `{"name", "phases": [{"title", "steps": [{"name","prompt",
    "output"?: JSON Schema 子集}]}]}`；`parent`(Any) 父 Agent（子代理继承其 provider/model）。
  - `name = spec.get("name", "workflow")`；`phases = spec.get("phases") or []`；
    `not isinstance(phases, list) or not phases` → `raise ValueError("workflow spec
    needs a non-empty 'phases' list")`。
  - `_emit("workflow/start", {"name": name, "parent": parent.id})`。
  - `results = {}`；`try:` 顺序遍历每个 phase：
    - `title = phase.get("title", f"phase-{len(results)+1}")`，`steps = phase.get("steps") or []`；
    - `_emit("workflow/phase", {"name", "phase": title, "steps": len(steps)})`；
    - 定义内层 `_run_step(step)`（见下）；
    - `pairs = await asyncio.gather(*(_run_step(s) for s in steps))`（phase 内 **并行**）；
    - `results[title] = dict(pairs)`。
  - `finally: _emit("workflow/end", {"name": name})`（无论成败）。
  - 返回 `{"name": name, "results": results}`。
  - **内层 `_run_step(step: Dict[str, Any]) -> tuple`**（第六批补结构化输出）：
    - `step_name = step.get("name", "step")`，`prompt = step.get("prompt", "")`；
    - `_emit("workflow/agent-start", {"name", "phase", "step": step_name})`；
    - `try`: `provider = self.ctx.subagents.get("in-process")`；
      `text = await provider.run(parent, f"workflow step {step_name}", prompt)`；
      `value = _parse_value(text)`；
    - **`output` schema 强制**：`output_schema = step.get("output")` 非空时
      `validate_value(value, output_schema, what="workflow step ... output")`
      （受支持子集）；`ToolError` → `value = {"invalid_output": True, "value": value,
      "error": str(exc)}`（不抛错、原值保留、标记 invalid_output）；
    - `_emit("workflow/agent-end", {..., "ok": True})`；返回 `(step_name, value)`。
    - `except Exception as exc`: `_emit("workflow/agent-end", {..., "ok": False,
      "error": str(exc)})`；返回 `(step_name, {"error": str(exc)})`（不抛出，隔离
      单步失败）。

**build_workflow_tool() -> Any**：

- 用 `define_tool` 注册 `workflow_run`：`timeout_ms=600_000`，`output={"type":"object"}`，
  `render=lambda args, value: json.dumps(value, ensure_ascii=False, indent=2)`；
  schema：`phases`（array，`required`；item 需含 `steps`（array，`required`），每 step
  需含 `prompt`（`required`），可含 `output`（object，该 step 输出 JSON Schema 子集，
  不匹配时结果带 `invalid_output`）。
- 内层 `async workflow_run(args, run_ctx)`：
  - `agent = run_ctx.execution.agent`；`None` → `ToolError("workflow_run requires a
    parent agent", code="NO_AGENT")`。
  - `ctx = agent.ctx if hasattr(agent, "ctx") else run_ctx.root_ctx`；
    `not ctx.has("workflowEngine")` → `ToolError("workflowEngine not mounted",
    code="NO_ENGINE")`。
  - `return await ctx.workflowEngine.run(args, agent)`。

**ToolWorkflowPlugin 函数/方法详解**：

- `__init__(self, ctx, config: Optional[dict] = None) -> None`：`self._disposer = None`。
- `apply(self, ctx) -> None`
  - `self._disposer = ctx.tools.register(build_workflow_tool())`；返回 `cleanup()`（调用
    disposer 并清空 `_disposer`）。

**事件**：`workflow/start`、`workflow/phase`、`workflow/agent-start`、
`workflow/agent-end`（含 `ok`，失败含 `error`）、`workflow/end`（TS `workflow/*` 子集）。

**关键流程伪代码**：

```
run(spec, parent):
  validate phases 非空 else ValueError
  emit("workflow/start")
  results = {}
  try:
    for phase in phases:
      emit("workflow/phase")
      pairs = await gather(*(_run_step(s) for s in phase.steps))  # 并行
      results[title] = dict(pairs)
    return {name, results}
  finally:
    emit("workflow/end")
```

**TS 对应**：dynamic workflow 的 phases/parallel 子集（见第 3 节差异）。

### 2.9 DeepSeek 适配器凭据回退（DeepSeekAdapterPlugin）

**定位与依赖**：`inject = ("llm",)`；回退读取 `ctx.credentials`（可选）。注册
`DeepSeekAdapter`（`name="deepseek"`，`supports_reasoning=True`）。

**字段表**：`_disposer`（注册的 unregister 函数）；`_adapter: Optional[DeepSeekAdapter]`。

**函数/方法详解**：

- `apply(self, ctx) -> None`
  - `config = self.config or {}`；`api_key = config.get("api_key") or
    os.environ.get("DEEPSEEK_API_KEY")`。
  - **凭据回退**：`if not api_key and ctx.has("credentials"):
    api_key = ctx.credentials.get("deepseek") or ""`。
  - `self._adapter = DeepSeekAdapter(api_key=api_key, base_url=config.get("base_url"),
    model=config.get("model"), timeout=float(config.get("timeout", 300)))`。
  - `self._disposer = ctx.llm.register_adapter(self._adapter)`；返回 cleanup。
  - 优先级：`config.api_key` > `DEEPSEEK_API_KEY` 环境变量 > `credentials.get("deepseek")`。

- `close(self) -> None`
  - `_adapter` 非空时 `asyncio.get_running_loop().create_task(self._adapter.close())`；

### 2.10 compaction 的 toolResultPruner 接入与 _estimate

**定位与依赖**：`CompactionService.provides = "compaction"`；
`CompactionPolicyPlugin.inject = ("compaction",)`。新增对 `ctx.toolResultPruner` 与
`ctx.tokenMeter` 的可选依赖。

**模块函数**：

- `estimate_tokens(messages: List[Any]) -> int`
  - `sum(len(block.text or "") for block in message.content) // TOKENS_PER_CHAR`
    （本地回退粗估，只算 `block.text`，常量 `TOKENS_PER_CHAR = 4` 在模块内重复定义）。

**函数/方法详解**：

- `CompactionService.compact(self, agent: Any) -> Dict[str, Any]`（含 pruner 接入）
  - `nodes = list(agent.session.surface.nodes)`；`len(nodes) <= self.keep_last_messages`
    → 返回 `{"compacted": False, "summary": "", "shadowed": []}`。
  - `shadowed = nodes[:-keep_last_messages]`；空则同上返回。
  - `history = session.derive_messages()`；
    `to_summarize = history[:len(history) - keep_last_messages]`。
  - **新增**：`if self.ctx.has("toolResultPruner"): to_summarize =
    self.ctx.toolResultPruner.prune(to_summarize)`。
  - `summary = await self._summarize(agent, to_summarize)`；
    `session.append("compaction/summary", {"summary": summary},
    surface_op={"op":"replace","start":shadowed[0],"end":shadowed[-1]},
    source_event_seqs=shadowed)`。
  - 返回 `{"compacted": True, "summary": summary, "shadowed": shadowed}`。
- `CompactionService._summarize(self, agent: Any, messages: List[Any]) -> str`
  - `text = "\n".join(m.plain_text() for m in messages)`；构造 `LlmRequest`
    （provider/model 取自 `agent.options.get("provider"/"model")`，缺省 `"mock"`），
    `system` 为「把以下对话历史压缩成不超过 500 字的要点摘要…」+ `text[:6000]`。
  - 流式：`async for chunk in agent._factory.ctx.llm.stream(request)` 经
    `AssistantAssembler` 拼接；`summary` 非空则返回 `"[早前对话摘要]\n" + summary`；
    异常（`log.exception`）/空则返回 `"[早前对话摘要]\n" + text[-2000:]`（本地截取兜底）。
- `CompactionPolicyPlugin._on_pre_step(self, payload: Dict[str, Any], next)`
  - `agent = payload.get("agent")`；非 None 时 `messages = agent.session.derive_messages()`，
    若 `self._estimate(messages) > self.ctx.compaction.threshold_tokens` 则
    `await self.ctx.compaction.compact(agent)`；最后 `return await next()`。
- `CompactionPolicyPlugin._estimate(self, messages: List[Any]) -> int`
  - **新增**：`if self.ctx.has("tokenMeter"): return self.ctx.tokenMeter.estimate(messages)`；
    否则回退模块级 `estimate_tokens(messages)`。

**接线**：`CompactionPolicyPlugin.apply` 以 `ctx.on("agent/pre-step",
self._on_pre_step, prepend=True)` 挂监听，返回调用 disposer 的 cleanup。

### 2.13 实现注意点（易踩坑）

1. **frozen dataclass 必须重建**：`Message`/`ContentBlock` 是不可变 dataclass，
   `ToolResultPrunerService.prune` 只能构造新对象，不能原地改 `block.content`。
2. **`limit = limit or default` 的 falsy 陷阱**：`SessionQueryService.list/search` 传
   `limit=0` 会被当作「未指定」回落到默认 50，无法表达「返回 0 条」。
3. **维护任务不派发 `agent/status`**：`run_maintenance` 直接 `create_task`，不经过
   `_set_status`，因此 UI 侧若只靠 `agent/status` 判断忙碌会漏掉维护期；应以
   `when_idle()` 为唯一静默判据。
4. **`_run_step` 用闭包捕获循环变量**：`WorkflowEngine.run` 中 `_run_step` 在 `for
   phase` 循环体内定义，闭包读取 `title`/`name`/`parent`/`self` 后随 `gather` 立即
   调用（`for phase in phases:` 每次迭代重新定义闭包），因此不存在 Python 经典
   「循环变量晚绑定」问题；但若未来改成 `lambda` 列表惰性求值需注意。
5. **`asyncio.gather` 不隔离异常**：workflow 单步异常已在 `_run_step` 内捕获并转为
   `{"error": ...}` 返回值，`gather` 本身不会抛；但 `subagents.get("in-process")`
   返回 `None` 时 `provider.run` 会抛 `AttributeError`（`None.run`），同样被
   `_run_step` 捕获为错误结果，而非中止整体。
6. **凭据回退的赋值链**：`DeepSeekAdapterPlugin.apply` 只在「三处都空」时才构造
   `api_key=""` 的适配器；`config.api_key` 为空串 `""` 会被 `or` 短路跳过，注意
   空串与未提供的等价语义。
7. **轮询扫描的目录剪枝**：`os.walk` 通过原地改 `dirnames[:]` 剪枝，若把
   `_SKIP_DIRS` 改成文件匹配会失效（它只过滤目录名）。
8. **`inspect()` 默认含崩溃修复**：`SessionQueryService` 的三类查询都会触发
   `repair_open_turn`，因此读到的「事件表」可能比磁盘原始行多一条合成 `turn/end`
   （`kind:'interrupted'`）。

## 3. 与 TS 版语义差异说明（如实标注）

1. **workflow 为 phases/parallel 最小版**：只支持「phase 顺序 + phase 内 step 并行」，
   无 TS 版条件分支、跨 phase 数据流编排、重试/依赖图；`spec` 仅 `{name, phases[]}`。
   单步失败被吞并封装为 `{"error": ...}` 而非中止整体；`workflow/end` 一定派发。
2. **`_extract_json` 为「配平提取」**：不是 `json.loads` 直读，而是扫描第一个
   `{`/`[` 起配平区间并尝试 `json.loads`，失败换下一个起点。字符串转义在扫描中处理，
   但**不处理**字符串外的注释/尾逗号（非标准 JSON 仍会失败）。`_parse_value` 失败
   时回退原文文本（而非报错）。
3. **AGENTS.md 轮询为 2s**（`config.interval` 默认 `2.0`）：子目录 on-touch 不是文件
   系统事件驱动，而是 `os.walk` + `(mtime_ns, size)` 快照比对 + `asyncio.sleep` 轮询；
   根 `AGENTS.md` 则每次 prompt 组装实时重读。`_root_seen` 字段声明但未用。
4. **sessionQuery 走 `inspect` 全量载入**：`list`/`search`/`trace` 都逐会话
   `inspect()`（默认 = `load`，含 `repair_open_turn`）把整个事件表读进内存再过滤，
   而非后端侧 SQL 过滤；无索引，代价随会话规模线性增长。`search` 只匹配
   `user/message`、`assistant/message`、`compaction/summary` 三类文本。
5. **tokenMeter 只计量 `block.text`**：`tool-result` 的 `content` 不参与估算；与
   pruner（作用于 `block.content`）覆盖维度不同。
6. **credentials 为单文件全量读写**：每次 `set`/`delete` 全量 `safe_dump` 覆盖，无
   增量；`set` 的事件派发吞异常、`delete` 不吞（不一致但为现状）。
7. **messageFeedback 持久化依赖 storage 存在**：未挂 `ctx.storage` 时仅内存、进程
   退出即丢；`_persist` 每次 `put` 全量覆盖该会话。`close()` 只清内存不落盘。
8. **runMaintenance 状态语义**：维护任务期间公共 `status` 保持 `idle`（不派发
   `agent/status`），`cancel()` 通过 `_maintenance.cancel()` 中止；`when_idle` 会
   `gather` 等维护任务完成才返回。`run_maintenance` 与 running/已有维护任务互斥。
9. **inspect 默认与 load 同构**：未在 JSONL/SQLite 后端做「只读头部」的省量覆写，
   当前 `inspect` 即 `load`（含崩溃修复）。
10. **workflow 结果结构与事件粒度**：`results` 以 `phase.title` 为键（标题重复会覆盖），
    以 `step.name` 为二级键；单步无 `name` 时用字面量 `"step"`；无 `title` 时用
    `phase-{序号}`。事件只报 `ok`/`error`，不回传中间文本。
11. **credentials.delete 与 set 的异常处理不对称**：`set` 的事件派发被 `try/except`
    吞掉，`delete` 未吞——若 `credentials/updated` 监听器抛异常，`delete` 会把异常
    抛回调用者而 `set` 不会，两者语义不一致（现状如此，未做统一）。
