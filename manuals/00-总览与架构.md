## 1. 项目定位

**dsh-python** 是 DeepSeek Harness（`dsh`）的 **Python 重实现**：用 Python 完整复刻其核心架构线——
「一切皆插件」的微内核、事件溯源会话、守卫工具管线、LLM 适配器接缝、Agent 驱动循环、
持久化、Profile/Bundle/Patch 组合，以及 FastAPI + 原生 JS 的流式 Web UI。

设计目标：**每一根架构线都能在 Python 里找到对应物**，模块名与 TS 版一一对应：

## 2. 五个基石概念（kernel）

| 概念 | Python 对应 | 一句话 |
|---|---|---|
| 插件即 Service | `dsh.kernel.Service`（`provides`/`inject`/`apply(ctx)`） | 挂载单元 |
| Context 是服务仓库 | `dsh.kernel.Context`（`ctx.tools`/`ctx.llm`…） | 按 key 解析，provider 可换 |
| inject 声明依赖 | Service.inject + Loader 拓扑排序 | 加载顺序自动推导 |
| 类型化事件 | `EventBus`：emit/waterfall/parallel/serial | 通信与扩展点 |
| 注册是可逆副作用 | `ctx.effect(disposer)` | 卸载逆序回滚（HMR 基础） |

### 2.1 四种事件派发（EventBus）

| 模式 | 是否 await | 顺序 | 有返回值 | 用途示例 |
|---|---|---|---|---|
| `emit` | 否（异步监听器转后台 task） | 注册序 | 无 | `session/event`、`agent/status` |
| `waterfall` | 是 | 洋葱中间件（`next()` 委派） | 有 | `tools/pre-execute`、`agent/pre-step` |
| `parallel` | 是 | 并行 | 无 | `session/flush` |
| `serial` | 是 | 顺序 | 有 | `agent/turn-stopping` |

waterfall 的关键语义：监听器签名 `handler(*args, next)`；调用 `await next()` 委派（返回值向上传播）；
不调用即短路（策略监听器惯用法）。

## 3. 运行时组合（boot）

```
空树
 → 各 bundle 行（base.yml，按 profile.bundles 顺序）
 → profile 的 cordis.patch.yml
 → home 级 ~/.dsh/cordis.patch.yml
 → --patch 覆盖层（--workspace / --mock / --provider）
 → 拓扑排序（provides/inject）→ 挂载（失败逆序卸载，fail loud）
```

一个配置行：`{id, plugin: "module:Attr", config: {...}, disabled?}`。
Patch 三操作：`{id, config}`（整体替换该行 config）、`{disable: [...]}`、`{insert: [...]}`。

## 4. 核心脊柱：一条 turn 的完整路径

```
AgentLoop._drive（驱动 task，idle 等唤醒）
 └─ _run_turn：append turn/start
     └─ _run_step（循环）:
        1. agent/pre-step waterfall（首步可 reject / enter(messages)）
        2. append step/start + user/message*
        3. system-prompt/assemble（分节 + 工具 schema）
        4. agent/request waterfall → LlmCallConfig
        5. llm/stream waterfall → 适配器 → assistant/chunk*（逐块入日志）
        6. append assistant/message（组装好的消息，source_event_seqs=chunk seqs）
        7. 工具调用循环: tool/call → ctx.tools.execute 五段管线 → tool/result
        8. append step/end → 'continue'（工具欠回复）/ 'stop'（自然停）
     └─ agent/turn-stopping serial（可 steer 出新一步）
     └─ append turn/end {reason}
```

铁律：**模型可见 = 已入日志**。任何进模型请求的内容都能从日志重建
（`request/header` 快照 + `derive_messages()` 派生）。

**配置热重载（HMR，对应 TS 版 watchUserPatches）**：`dsh/config/watcher.py` 的
`ConfigWatcherPlugin` 轮询 profile/home 两级 `cordis.patch.yml`（mtime+hash），
变更即应用——id+config 替换热更新（`Service.reconfigure` 钩子，失败回滚旧配置）、
disable 卸载、insert 增量挂载；解析失败发 `hmr/config-update-failed` 保持旧树。
`boot()` 把树注入 `ctx.pluginTree` 供 watcher 做运行期增量操作。

## 5. 工具五段管线（tools）

```
tools/pre-execute  (waterfall: allow/deny/ask → 审批服务解析 ask)
  → 单调 guards（只能收窄权限）
  → tools/execute   (around-dispatch: 超时/重试/指标包装)
  → tools/post-execute (waterfall: accept/替换/block)
  → finalize_content（定义自有最后一里路变换）
  → tools/result    (emit: 不可变权威结果)
```

参数在策略前一次性物化+冻结；`ToolExecution` 身份只读；未知工具/抛错工具 → 结构化失败（不结束 turn）。

## 6. 会话日志（session）

- 只追加 `SessionEvent {type, seq, time, data, surface_op?, source_event_seqs?, ignorable?}`；
- `append` 在源头做无损失 JSON 校验（坏事件进不了日志）；
- surface 事件（user/message、assistant/message、tool/result、compaction/summary）
  必须声明 `surface_op`（append / replace 区间）；
- `derive_messages()` 走 surface 节点序投影模型历史（replace 删除被遮蔽节点）；
- `session/event` 是**同步通知**（持久化插件同步入缓冲，异步监听器由 flush 前排空）。

## 8. 自定义四层次

1. **改配置**：`~/.dsh/profiles/<name>/cordis.patch.yml` 按 id 覆盖/禁用/插入行（无需改代码）；
2. **装插件**：写一个 `Service` 子类，用 insert 行挂进 profile（见 `examples/my_plugin.py`）；
3. **换 provider**：实现对应抽象类（如 `LlmAdapter`），注册即可整体换行为；
4. **改内核**：`dsh/` 下一切皆可替换——扩展事件词汇用 `register_event_type`，
   扩展工具用 `ctx.tools.register`，扩展提示用 `ctx.systemPrompt.section`。
